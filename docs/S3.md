# S3

`Kralizek.Lambda.Template.S3` supports two distinct S3-to-Lambda models: native S3 event notifications and S3 Batch Operations.

## Event notifications

Derive from `S3Function<THandler>` and implement `IS3ObjectEventHandler`. The handler receives a synthetic `S3ObjectEvent` with an `S3ObjectReference`, event name, event time, and sequencer. The original AWS record remains available through `S3RecordContext.GetS3EventRecord()`.

The synthetic model deliberately presents object identity and event metadata without requiring application code to depend directly on the complete AWS notification envelope. `S3EventName` is forward-compatible and includes helpers for known event families.

## S3 Batch Operations

Derive from `S3BatchFunction<THandler>` and implement `IS3BatchItemHandler`. The integration supports S3 Batch Operations invocation schema 2.0.

Handlers receive an `S3BatchItem`. Object tasks use `S3BatchObjectKey`, composed with the same `S3ObjectReference` model used by notifications. Raw request/task data remains available through `S3BatchContext`.

Return `S3BatchResult.Succeeded()`, `S3BatchResult.TemporaryFailure()`, or `S3BatchResult.PermanentFailure()` for each task. Unexpected exceptions fail the Lambda invocation instead of having retry semantics inferred by the framework.

Both S3 models currently process records/tasks sequentially.
